测试方法

Case 来源 脚本内置 10 个 DataAgent 前端典型问题，例如 SSE 流式输出、ECharts 报告渲染、数据源配置、Human Feedback、会话状态恢复等。
标准答案 每个 case 配置 1 到 3 个期望命中文件，只要 TopK 结果里出现任意期望文件就算命中。
Baseline 只使用自动 README 内容和源码路径做关键词检索，模拟“没有结构化 codebase index”的情况。
Enhanced 使用 .scripts/codebase-index.json 里的文件、符号、行号、类型、summary、searchText 做结构化检索。
Token 口径 不调用真实模型，不产生 API token 账单；token 是对 TopK 检索结果上下文 payload 的本地估算，用于比较上下文成本。

指标解释

指标 怎么理解 面试时可以怎么说
Top1 正确文件是否排在检索结果第 1 位。 代表“AI 第一眼能不能定位到正确代码”。
Top3 正确文件是否出现在前 3 个结果里。 代表“AI 在较小上下文预算内能不能拿到关键文件”。
Top5 正确文件是否出现在前 5 个结果里。 代表“检索是否基本覆盖相关上下文”。
MRR Mean Reciprocal Rank。正确文件排第 1 位得 1 分，第 2 位得 0.5 分，第 3 位得 0.333 分；没命中得 0 分，再对所有 case 取平均。 它比命中率更能体现排序质量，正确结果越靠前，MRR 越高。
Estimated Tokens 本脚本不调用 LLM，所以这里是本地估算：中文约 1.5 字/token，非中文约 4 字符/token，统计 TopK 检索结果会进入上下文的 payload。 代表“同样解决问题时，大概要给模型塞多少检索上下文”，越低通常越省钱、越省上下文窗口。
